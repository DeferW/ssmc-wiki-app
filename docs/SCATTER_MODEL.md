# Вкладка «Отдача»

Сборка оружия общая с вкладкой «Одна сборка». Справа отображаются полигон,
минимальный/максимальный сектор, сектор последнего выстрела и следы пуль.
Поддерживаются одиночный спуск, очередь и непрерывная автоматическая серия.
При изменении сборки старые следы и таймер очищаются. Следов хранится не более
240; число выстрелов в автоматической серии ограничено 60 для интерфейса.

## Формулы

Минимум — wielded scatter. Дополнительный максимум зависит от режима и
множителя burst scatter (включая обвесы); отрицательное дополнение ограничено
нулём. Приращение — разница базовых максимума и минимума, делённая на
shotsToMaxScatter, либо явно заданный scatterIncrease. Затем обвесы последовательно
меняют минимум и максимум; приращение при этом не пересчитывается.

Перед выбором направления игра увеличивает текущий угол, вычитает спад за
время и ограничивает его минимумом и максимумом. Направление равномерно выбирается
в пределах ± половины полного угла. Поэтому первый выстрел автоматической серии
уже может быть шире минимального сектора. После отпускания спуска новый спуск
начинается с минимума. Веер дроби расположен равномерно вокруг исходного mapAngle, сохранённого до
GetRecoilAngle: текущая реализация игры не поворачивает его случайным разбросом
оружия. Поэтому на полигоне для дроби минимум и максимум совпадают;
scatterFlat обвесов добавляется к полному углу веера с коэффициентом 1/2.

CameraRecoilScalar — отдельный коэффициент толчка камеры; импульс равен
0.5 × коэффициент. Он не прибавляется к углу пули. Движение камеры и её
восстановление во времени не анимируются и не выдаются за траекторию оружия.

## Данные и ограничения

`weaponStats.ballistics` версии 1 нормализуется в data модулем
`scripts/catalog/ballistics.py`. Отсутствующее поле не заменяется придуманными
значениями на клиенте. Поддерживаются базовые параметры RMCSelectiveFire;
особые системы (например GunSpinup) помечаются как неподдерживаемые.
Значения C# по умолчанию хранятся в data рядом с проверенным commit источника.
Новые игровые компоненты требуют расширения нормализации и тестов.

Расчёт — для сборки в двух руках без поправок на навыки, движение, баффы,
двойное оружие, накал и другие динамические состояния. Это не модель попадания
в моба: столкновения, размеры хитбоксов, вероятностные промахи, урон и скорость
полёта здесь не рассчитываются. Math.random служит визуальной выборкой внутри
проверенных границ; серверный seed/PRNG и конкретные выстрелы не воспроизводятся.

Фон `src/assets/range-reference.png` — предоставленный пользователем скриншот,
скопированный без изменения. Все секторы, линии и отметки нанесены отдельным SVG.
У фоновых стен и цели нет физики. Автомасштаб по максимальному сектору позволяет
показывать широкие углы без обрезки; пиксели скриншота не являются измеренной
дистанцией в игровых метрах.

## Публикация

Сначала опубликовать обновлённый каталог в data, затем Deploy GitHub Pages в app.
Build catalog включает новое поле автоматически. Для существующего каталога
того же исходного commit можно отдельно выполнить в data:

```sh
python -m scripts.catalog.ballistics --catalog data/catalog/catalog.json
python -m scripts.catalog.ballistics --catalog data/maps/static-items.json
```

Команда читает уже разрешённые свойства предметов и обновляет только дополнительное
поле ballistics. Пересборка карт не нужна.
