# Инвентаризация констант

Перечень для обсуждения следующего этапа. Игровые числовые значения в этой
итерации не менялись. Это не предложение заменить все числа настройками:
параметры механики должны происходить из данных игры, параметры интерфейса и
ограничения ресурсов остаются ответственностью приложения.

Не возвращать их в таблицы по ID оружия. Само наличие default в C# не означает,
что число можно автоматически извлечь из YAML: сборщику нужны проверенное
зеркало default, ссылка на исходник и тест, либо явный этап чтения кода механики.

## Редакторские решения

- `MIXTURE_PRESETS`: рецепт «Унга» (пять компонентов по 180u, DexalinPlus 20u,
  Iron и Sugar по 40u) и текст «до 80u без передоза». Состав можно вынести в
  конфигурацию рецептов; утверждение о передозе лучше вычислять по данным смеси.
- `MARINE_PRESETS`: ID наборов брони/экипировки. Характеристики уже берутся из
  каталога; сами варианты комплектов можно хранить в редакторском JSON.
- `PLANNER_WEIGHTS`: 10^12, 10^9, 10^6, 10^3, 1, 0.001. Это порядок предпочтений
  маршрутов, а не физика игры. Возможная замена — лексикографическое сравнение
  критериев с регрессионными тестами; отдельно решить приоритет удобства и расхода.
- Словари названий, ролей, маркеров и цветов в maps — слой представления;
  локализуемые названия по возможности должны приходить из data.

## Оставить техническими параметрами

Очередь карт (6 запросов), память (128 МиБ), 3 попытки с backoff, 512px тайл,
качество WebP 82, бюджет публикации карт 512 МиБ; таймаут JSON 12s; предел
симуляции 300 выстрелов; допустимый zoom, чувствительность колеса, кеши значков,
размеры UI и численный epsilon. Эти значения имеют разные назначения и не
должны сливаться в один глобальный файл constants.

В data также остаются: `RMC_SIZES`, `AREA_SUPPORT_FIELDS`, версии схем,
`MARINE_BASE_PROTOTYPE_ID`, `STORIES_SHIP_PROTOTYPE_ID`, корни источников,
минимальный объём валидации мобов, словари классификации и C# defaults в
`scripts/catalog/statistics.py`, `scripts/common/items/prototypes.py` и
`scripts/mobs/build.py`. Часть уже является явной конфигурацией
(`catalog-sources.yml`, `map-objects.json`); остальные переносить только при
появлении реальной необходимости менять их без изменения алгоритма.

## Предлагаемый порядок следующей работы

1. Согласовать оборудование химии и правила источников реагентов.
2. Расширить карточки оружия и mobs способностями и default-механиками.
3. Добавить контрактные тесты на совпадение сборщика и потребителя.
4. Пересобрать соответствующие наборы из зафиксированного commit игры.
5. После публикации данных удалить совместимые fallback из app.

Числа из игровых комментариев в этом документе описывают текущий код проекта;
повторная сверка с актуальной версией игры потребуется перед переносом.
