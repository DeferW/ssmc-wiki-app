# Roadmap архитектуры SSMC Wiki

Этот файл хранит согласованные планы, которые ещё не реализованы. Он не
описывает текущее поведение production-сборки.

## Перенос catalog overrides в сайт

**Статус:** запланировано, реализация отложена.

### Цель

Разделить игровые данные и редакторские решения:

- `ssmc-wiki-data` собирает полный нейтральный каталог из исходников игры;
- сборщик сохраняет автоматическую категорию, характеристики, связи и сигналы
  классификации, но не применяет редакторские overrides;
- `ssmc-wiki-app` становится владельцем ручных изменений категорий по аналогии
  с локальным `EXCLUDED_WEAPON_IDS`;
- итоговая категория и отметка `EDITED` вычисляются в приложении после загрузки
  базового каталога;
- `Скрытые` остаётся полноценной override-категорией, а не полем `hidden`;
- скрытый предмет не показывается в обычной выдаче, но остаётся доступен через
  связи других предметов и прямое открытие карточки.

### Предполагаемая схема

```text
репозиторий игры
       ↓
ssmc-wiki-data → полный catalog.json с automaticCategory
       ↓
ssmc-wiki-app → применяет собственные overrides → каталог для пользователя
```

### План миграции

1. Убедиться, что `catalog.json` содержит все данные до применения overrides и
   стабильную `automaticCategory` для каждого предмета.
2. Перенести существующий `config/catalog-overrides.json` в конфигурацию сайта
   без потери записей.
3. Добавить в приложении единый слой наложения категорий. Каталог, поиск,
   карточки и admin-интерфейс должны использовать только его результат.
4. Сохранить возможность редактирования через Worker. Способ хранения — файл в
   репозитории приложения или отдельное API-хранилище — выбрать при разработке
   полноценной авторизации.
5. После переходного периода удалить чтение и применение overrides из
   сборщика, его workflow и документации.
6. Добавить контрактные тесты: обычная категория, изменённая категория,
   `EDITED`, `Скрытые` и открытие скрытого предмета через связь.

### Важное ограничение

Нельзя сначала удалить overrides из сборщика, а затем переносить UI. Миграция
должна быть совместимой: сначала сайт учится применять тот же набор правил,
после чего редакторский слой отключается в `ssmc-wiki-data`.
